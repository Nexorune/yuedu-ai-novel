## 1. 用户问题与背景

### 1.1 痛点与机会

市面上的学习产品普遍存在两个痛点：

- **学习反人性**：用户知道「应该学」但缺乏持续动力，打卡难以坚持，留存普遍偏低。
- **网文只有爽感没有收获**：用户沉迷追更，但读完「除了爽什么都没留下」，难以形成长期价值沉淀。

本产品把两者绑定：用「追更的爽感」驱动「学习打卡」，让用户边追边学。

### 1.2 产品定位

一款把「追网文的爽感」和「学习打卡」绑定的生成式内容产品：用户选小说类型 + 输入想学的主题，系统按章生成个性化小说与配套测验，答对解锁下一章。

一句话价值主张：**「边追更，边学东西」——每一章爽完之后，顺手把知识带走。**

### 1.3 与现有方案的差异

| 维度 | 传统刷题 / 知识付费 | 本产品 |
|-|-|-|
| 学习动力 | 靠意志力 / 外部监督 | 靠「追更爽感」+「解锁闯关」内在驱动 |
| 内容形态 | 固定课程、固定题库 | 按用户类型 + 主题实时生成的个性化小说 |
| 留存抓手 | 打卡、连续天数 | 剧情钩子 + 多结局收集 |

## 2. 目标与成功标准

### 2.1 北极星指标

**周留存率**：本周至少完成 1 次答题的用户，在下周仍至少完成 1 次答题的比例。

### 2.2 分阶段目标

| 阶段 | 目标 | 判定标准 |
|-|-|-|
| 本地验证期（当前） | 验证生成质量和主流程 | 真实样例打分达到「生成质量标准」；在网页上完整走通一本书 |
| 上线验证期（对外上线后 4 周） | 验证「边追边学」模式成立 | 周留存 ≥ 30% |
| 增长期 | 验证规模化与变现 | 周留存 ≥ 30%，单用户日均 1–3 章 |

### 2.3 指标体系

| 指标 | 目标值 | 说明 |
|-|-|-|
| 周留存 | ≥ 30% | 核心指标，自然周口径，连续观察 4 周 |
| 单章完读率 | ≥ 60% | 读完正文才进入答题的用户占比 |
| 答题正确率 | 50%–70% | 区间指标：低于 50% 题太难（劝退），高于 70% 题太简单（没学到），均触发难度调整 |
| 单章生成时延 | ≤ 3 分钟 | 异步生成，用户提交后先返回 |
| 单章生成成本 | ≤ 几分钱 | 按实际用量计费，由每日上限和每月上限兜底 |
| 每月模型费用 | ≤ 50 元 | 花到上限自动停止生成，额度可调整 |

指标口径说明：周留存的「至少完成 1 次答题」需在开发前与数据方确认最终口径（是否计登录、是否计读题）；上线前完成对齐。

### 2.4 生成质量标准

AI 每次生成的内容都不一样，所以「写得好不好」要事先约定标准。这些标准来自真实样例打分和试用反馈，之后每次验收都按它来。

| 打分维度 | 看什么 |
|-|-|
| 覆盖要求 | 本章列出的知识点都讲到了，核心知识点讲清了含义和用法 |
| 结构合规 | 正文和 5 道题都齐全，格式正确 |
| 语言质量 | 读起来通顺自然 |
| 事实无误 | 讲到的知识本身没有错误 |
| 长度合适 | 正文篇幅在可接受范围内 |

**达标线：**每个维度 1–3 分，5 个维度平均不低于 2 分，且没有一条样例被标为「不能接受」。

**硬性要求：**测验只考学习主题的知识，不考人物、剧情和小说里的场景细节；出现考剧情的题即为不合格。

**可以接受的瑕疵：**偶尔前后情节对不上、个别题目有争议、正文写到 4000 字左右。

**由谁判断：**产品经理用 5–10 条真实样例打分。

## 4. 目标用户与关键场景

### 4.1 用户画像

- **年龄段**：18–35 岁
- **核心特征**：爱看网文（爽文 / 言情 / 都市等），同时有碎片化学习意愿（想学 AI、英语、理财等，但坚持不下来）
- **典型场景**：通勤、睡前、午休等碎片时间，手机阅读
- **使用方式**：单用户线性使用，非多人协作

### 4.2 用户故事

1. 作为「想学 AI 但看不进教材」的用户，我希望用爽文的形式学 AI 概念，这样我能坚持读完。
2. 作为「只有几分钟碎片时间」的用户，我希望输入一个词（如「复利」）就能立刻得到一篇短故事 + 测验。
3. 作为「读到一半失去兴趣」的用户，我希望随时能「就此完结」，得到一个有头有尾的结局，而不是烂尾。
4. 作为「喜欢收集」的用户，我希望完结后还能解锁不同风格的结局，反复体验。

### 4.3 关键流程

整本模式主流程：

1. 18+ 年龄确认
2. 选小说类型 → 输学习主题 → 设章节数 → 设篇幅
3. 系统生成全书大纲 + 建立故事档案 + 随机暗定结局（不透露）
4. 循环：读下一章（后台生成 → 审核 → 校验）→ 展示正文 → 答题（5 题对 3）；用户答题时，后台已在提前准备下一章
5. 通过则解锁下一章；失败则进入失败降级
6. 读完计划章节或用户选择「就此完结」→ 生成大结局章（回收全部伏笔）
7. 完结后解锁「结局画廊」，可重走其他结局

快速短篇流程：输入一个词 / 知识点 → 生成 1 章短篇 + 测验 → 答题 → 完结 → 结局画廊。

## 5. 功能需求与验收

### 5.1 F1 新建小说

用户输入：小说类型（爽文 / 言情 / 都市 / 玄幻 / 悬疑）、学习主题（自由文本）、章节数（1–50）、每章篇幅（最少字数默认 1500、最多字数默认 2500）。

系统在创建时完成：为小说取一个书名（书架和阅读页显示书名，学习主题作为副标题）、生成全书大纲（三幕结构）、建立故事档案、随机暗定结局风格（不向用户透露）。

验收：

- 给定类型 + 主题 + 章节数 + 篇幅，系统能创建书籍并生成覆盖全部章节的三幕大纲。
- 结局风格从 4 种（圆满 / 反转 / 开放 / 悲剧）中随机选出且界面上不展示。
- 未满 18 岁的确认被拒绝后无法创建。
- 新建的书有自己的书名，书架和阅读页都能看到。

### 5.2 F2 快速短篇

用户只输入一个词或知识点（如「蝴蝶效应」），系统以该词为核心知识点，自动补 2 个关联辅助知识点，生成 1 章短篇 + 5 道测验。

验收：

- 输入单个词后，能生成 1 章含该词的短篇与 5 道题。
- 本质为 planned_chapters=1 的书籍，复用 F4–F9 的全部逻辑。

### 5.3 F3 逐章生成与阅读

异步生成：第 1 章由用户发起，在后台生成，完成后展示。之后每一章都提前生成：用户打开本章答题区时，后台就开始生成下一章（已是计划的最后一章时不提前生成）。本章答对之前看不到下一章；答对后点「读下一章」直接阅读，还没生成完就显示进度。按章交付，不整本一次生成。

单章要求：正文目标 1500–2500 字，写到 4000 字左右也可以接受，少于最少字数要重写；每章 5 道题；正文标注「（AI 生成内容）」。每章固定 3 个知识点（1 核心 + 2 辅助），核心知识点在剧情中自然出现 2–3 次。

验收：

- 单章正文不少于设定的最少字数、最多 4000 字左右，题目数为 5。
- 正文包含「AI 生成内容」标注。
- 每章知识点恰为 1 个核心 + 2 个辅助。
- 本章答题通过之前，读不到已提前生成的下一章。

### 5.4 F4 答题与解锁

每章 5 道题，答对 ≥3 题（60%）解锁下一章。题目结构：核心知识点 3 题（记忆 → 理解 → 迁移），2 个辅助知识点各 1 题（定位题）。每题带 source_paragraph（对应段落），答错可提示「回看第 X 段」。题目只考学习主题的概念、原理和实际应用，不能考人物、剧情和小说里的场景细节；题干考的是剧情，即使选项里提到真实知识，也算不合格。

验收：

- 答对 3 题及以上解锁下一章；答对不足 3 题不解锁。
- 题目只能覆盖本章已列出的 3 个知识点，不超纲。
- 每题能回溯到对应段落。
- 5 道题里没有考剧情的题。

### 5.5 F5 失败降级（绝不卡死用户）

| 连续失败次数 | 系统行为 |
|-|-|
| 第 1 次 | 展示错题 + 答案在原文的位置提示；可重读原文；「重新答题」换一套新题（防背答案） |
| 第 2 次 | 提示「题目可能偏难」，换题为偏简单难度（答案尽量能在原文找到） |
| 第 3 次及以上 | 自动降到最易（纯定位送分题），并上报「本章内容可能有问题」 |
| 任意时（上线前做） | 用户可点「这题有问题」→ 该题作废不计分，按剩余题数重新判定（作废 1 题后按 4 题对 ≥3 算） |

核心原则：**难度可一路降到「答案就在原文里」的送分题，理论上一定能过，绝不永久卡死；只有题烂才作废题，不作废整章。**

验收：

- 答错后能看到每道错题对应的原文段落提示。
- 重新答题时题目与上一套不同。
- 连续失败 3 次后题目为「答案直接在原文中」的送分题。
- 标记争议题后，该题不计入总分（上线前做）。

### 5.6 F6 章节衔接（全书大纲 + 故事档案）

生成第 1 章前先生成全书大纲（三幕结构，章节区间完整覆盖全部章节）。维护随章节更新的故事档案，含：人物卡、主线设定、每章一句话摘要、未回收伏笔表、已学知识点清单。每章生成时注入前情摘要 + 最新人物卡 + 未回收伏笔。

验收：

- 第 N 章的人物姓名、身份、关系与第 1 章设定一致。
- 大纲三幕的章节区间无空档，完整覆盖 1 到总章数。
- 后续章节不重复已学知识点出题。

### 5.7 F7 内容审核与连贯性校验

生成内容必须通过审核（模型自审 + 关键词兜底），不写暴力 / 色情 / 违法 / 危险模仿内容，不过则重写（最多 2 次）。每章生成后校验人物、关系、前情与档案是否一致，矛盾则自动重写。

验收：

- 命中敏感词或模型自审判定不安全的内容不会交付给用户。
- 审核 / 校验不通过时自动重写，超过 2 次则降级为「保守模板章」（上线前做）。

### 5.8 F8 完结与结局画廊

任意章节答完题后可选「继续下一章」或「就此完结」；选完结立即生成大结局章（回收全部未回收伏笔），不论原计划还剩几章。结局风格在开书时随机暗定、阅读全程不透露，完结时按暗定风格生成。完结后解锁「结局画廊」，可「重走一个结局」——复用前面所有章节 + 故事档案，只重新生成大结局章（不同风格），逐次解锁、可收集多结局。

验收：

- 阅读过程中任何界面都不展示暗定结局风格。
- 「就此完结」后生成的大结局章回收了故事档案中全部未回收伏笔。
- 重走结局只新增大结局章，不改动已生成的正文章节。

### 5.9 F9 进度保存与续读

记录用户已解锁到第几章、连续失败次数、每日生成次数；会话中断后可从上次进度继续。

验收：

- 退出后重新进入，能恢复到上次已解锁章节。
- 每日生成次数跨会话累计，超过 20 章/用户/天后拒绝新生成（失败重试不计数）。

## 6. 异常与边界

### 6.1 异常处理

| 场景 | 处理 |
|-|-|
| 生成调用失败 | 自动重试 1–2 次，仍失败则提示「稍后再试」，不扣额度 |
| 审核不通过 | 自动重写，最多 2 次；超过则降级为「保守模板章」（上线前做） |
| 篇幅 / 题量不达标 | 自动重写，最多 2 次 |
| 连贯性不通过 | 自动重写，最多 2 次 |
| 单章超时（大于 3 分钟） | 中止并重排，通知用户「仍在生成中」，不阻塞已解锁章节 |
| 越权访问（读未解锁章） | 拒绝并记录 |
| 题目幻觉（答案与正文对不上） | 标记「此题有争议」，可作废该题，不卡用户（上线前做） |

### 6.2 安全与合规红线

1. **内容审核**：生成内容必须过审核（模型自审 + 关键词兜底），不写暴力 / 色情 / 违法 / 危险模仿，不过则重写。
2. **年龄保护**：面向 18+ 成年人，MVP 用自声明确认（产品化后换实名 / 支付校验）。
3. **版权声明**：明确「AI 生成内容」，不改编现实真实网文。
4. **越权拒绝**：不能访问未解锁章节。

## 7. 质量约束（非功能需求）

### 7.1 性能

- 单章生成时延 ≤ 3 分钟（异步，用户提交后先返回）。
- 单章正文目标 1500–2500 字（最多 4000 字左右）+ 5 道题。

### 7.2 成本

- 单章生成成本 ≤ 几分钱。
- 每月模型费用上限 50 元：花到上限自动停止生成，额度可调整。
- 每日生成上限：20 章/用户/天（防滥用），失败重试不计数。

### 7.3 可观测性

- **日志**：每章生成请求（章节号、生成设置、起止时间）、审核结果、解锁动作、工具失败与重试链。
- **指标**：周留存、单章完读率、答题正确率、单章时延、单章成本（上线前做）。
- **轨迹**：按「用户 + 章节」记录完整轨迹（生成参数 → 模型调用 → 审核 → 校验 → 落库 → 解锁 → 答题结果）（上线前做）。

### 7.4 数据与隐私

- 书籍、章节和阅读进度只存在本机。
- 日志不记录完整正文，也不记录密钥。
- 生成内容需要调用外部模型服务（见「外部依赖」）；内容审核用模型自审加本地关键词兜底，不再另外发给第三方审核服务。

## 8. 依赖与开放问题

### 8.1 外部依赖

- 模型服务：deepseek-v3.2，通过 aihubmix 平台调用。
- 存储：SQLite 单文件（MVP）。
- 内容审核：模型自审 + 本地关键词兜底（MVP，V1.1 可接外部审核 API）。

### 8.2 版本规划

| 版本 | 内容 |
|-|-|
| MVP（P0） | F1–F9 全部；网页版（电脑和手机浏览器都能用），本机运行，单人使用 |
| V1.1（P1） | 对外上线；真实账号登录；补齐标「上线前做」的条目；内容审核接外部 API；正确率自动调难度的独立评估器 |
| 二期（P2） | 支付、消息推送、独立题库、MCP 插件生态、跨会话偏好记忆 |

### 8.3 风险与开放问题

| 风险 / 问题 | 说明 | 应对 |
|-|-|-|
| 章节断章 | AI 写长篇可能前后矛盾 | 故事档案 + 连贯性校验 + 自动重写 |
| 内容安全 | 生成式内容合规风险 | 模型自审 + 关键词兜底 + 18+ 门槛 + AI 标注 |
| 题目幻觉 | 答案与正文对不上 | 出题只从知识点清单出 + source_paragraph 锚定 + 争议题作废 |
| 成本失控 | 长篇字数膨胀 | 篇幅限制 + 每日上限 + 每月 50 元上限（到顶自动停） |
| 提前生成多花钱 | 答题时已提前生成下一章，用户随后选「就此完结」，这一章就白生成了 | 接受这部分费用，换取读下一章不用等；由每月上限兜底 |
| 「周留存 ≥30%」统计口径 | 自然周内几次答题算留存未定 | 上线前确认：≥1 次答题 |

## 9. 验收标准

| 验收项 | 怎么算通过 | 对应章节 |
|-|-|-|
| 主流程走通 | 在网页上完整走一遍：新建书 → 读 → 答题 → 解锁 → 就此完结 → 结局画廊 | 关键流程、F1–F9 |
| 生成质量达标 | 用 5–10 条真实样例打分，达到「生成质量标准」 | 生成质量标准 |
| 不卡住用户 | 连续答错也能过关；生成失败时有提示，可以重试 | F5、异常处理 |
| 数据不丢 | 关掉再打开，书和阅读进度都还在 | F9 |
| 费用可控 | 当月模型费用到 50 元会自动停止生成 | 成本 |

## 10. 术语表

| 术语 | 含义 |
|-|-|
| 爽文 | 以「主角逆袭、打脸反派」为核心爽点的网文体裁 |
| 故事档案（Story Bible） | 随章节更新的持久化档案，保证跨章连贯 |
| 三幕结构 | 开局 → 发展 → 高潮结局 的叙事框架 |
| 暗定结局 | 系统在开书时随机选定、不向用户透露的结局风格 |
| 结局画廊 | 完结后可重走多结局的收集界面 |
| 迁移题 | 考察把知识点应用到新场景的能力的题目 |
| 争议题 | 答案与正文对不上、可由用户标记作废的题 |
