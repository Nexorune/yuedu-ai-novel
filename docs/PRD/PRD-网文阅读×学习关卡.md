## 1. 用户问题与背景

### 1.1 痛点与机会

市面上的学习产品普遍存在两个痛点：

- **学习反人性**：用户知道「应该学」但缺乏持续动力，打卡难以坚持，留存普遍偏低。
- **网文只有爽感没有收获**：用户沉迷追更，但读完「除了爽什么都没留下」。

本产品把两者绑定：用「追更的爽感」驱动「学习打卡」，让用户边追边学。

### 1.2 产品定位

一款把「追网文的爽感」和「学习打卡」绑定的生成式内容产品：用户输入想学的知识、选一种故事类型，系统按章生成个性化小说与配套测验，答对解锁下一章。

一句话价值主张：**「边追更，边学东西」——每一章爽完之后，顺手把知识带走。**

### 1.3 与现有方案的差异

| 维度 | 传统刷题 / 知识付费 | 本产品 |
|-|-|-|
| 学习动力 | 靠意志力 / 外部监督 | 靠「追更爽感」+「解锁闯关」内在驱动 |
| 内容形态 | 固定课程、固定题库 | 按用户主题 + 类型实时生成的个性化小说 |
| 留存抓手 | 打卡、连续天数 | 剧情钩子 + 多结局收集 + 知识卡片沉淀 |

## 2. 目标与成功标准

### 2.1 北极星指标

**周留存率**：本周至少完成 1 次答题的用户，在下周仍至少完成 1 次答题的比例（「完成 1 次答题」= 至少答完 1 道题，以登录账号为单位统计）。

### 2.2 分阶段目标

| 阶段 | 目标 | 判定标准 |
|-|-|-|
| 本地验证期（已完成） | 验证生成质量和主流程 | 真实样例打分达到「生成质量标准」；在网页上完整走通一本书 |
| 演示版（当前目标） | 面试时完整演示一个「像已上线」的产品 | 从落地页 → 登录 → 新建 → 阅读 → 闯关 → 完结，一次走通不出错；页面完整、文案统一、无明显开发痕迹 |
| 内测期 | 小范围真实用户验证「边追边学」 | 周留存 ≥ 30% |
| 公开上线期 | 验证规模化与付费 | 周留存 ≥ 30%，单用户日均 1–3 章；收费方式另定 |

### 2.3 指标体系（内测期起统计）

| 指标 | 目标值 | 说明 |
|-|-|-|
| 周留存 | ≥ 30% | 核心指标，自然周口径，连续观察 4 周 |
| 首本书完成第 1 章率 | ≥ 70% | 新用户注册后读完第 1 章并答完题的比例 |
| 单章完读率 | ≥ 60% | 读完正文才进入答题的用户占比 |
| 答题正确率 | 50%–70% | 低于 50% 题太难，高于 70% 题太简单，均触发难度调整 |
| 单章生成时延 | ≤ 3 分钟 | 异步生成，用户提交后先返回 |
| 每月模型费用 | 全站 ≤ 50 元（可调） | 到上限自动停止生成 |

### 2.4 生成质量标准

AI 每次生成的内容都不一样，所以「写得好不好」要事先约定标准。这些标准来自真实样例打分和试用反馈，之后每次验收都按它来。

| 打分维度 | 看什么 |
|-|-|
| 覆盖要求 | 本章列出的知识点都讲到了，核心知识点讲清了含义和用法 |
| 结构合规 | 正文和 5 道题都齐全，格式正确 |
| 语言质量 | 读起来通顺自然 |
| 事实无误 | 讲到的知识本身没有错误 |
| 长度合适 | 正文篇幅在可接受范围内 |

**达标线：**每个维度 1–3 分，5 个维度平均不低于 2 分，且没有一条样例被标为「不能接受」。

**硬性要求：**测验只考学习主题的知识，不考人物、剧情和小说里的场景细节；出现考剧情的题即为不合格。

**可以接受的瑕疵：**偶尔前后情节对不上、个别题目有争议、正文写到 4000 字左右。

**由谁判断：**产品经理用 5–10 条真实样例打分。

## 4. 目标用户与关键场景

### 4.1 用户画像

- **用户范围**：喜欢故事阅读、希望学习知识的人群；不设成年登录门槛
- **核心特征**：爱看网文，同时有碎片化学习意愿（想学 AI、英语、理财等，但坚持不下来）
- **典型场景**：通勤、睡前、午休等碎片时间，手机阅读
- **演示版的实际使用者**：产品经理本人，在面试中向面试官演示

### 4.2 用户故事

1. 作为「想学 AI 但看不进教材」的用户，我希望用爽文的形式学 AI 概念，这样我能坚持读完。
2. 作为「只有几分钟碎片时间」的用户，我希望输入一个词（如「复利」）就能得到一篇短故事 + 测验。
3. 作为「读到一半失去兴趣」的用户，我希望随时能「就此完结」，得到一个有头有尾的结局。
4. 作为「喜欢收集」的用户，我希望完结后还能解锁不同风格的结局。
5. 作为新用户，我希望用手机号就能直接登录，不用填一堆资料。

### 4.3 页面清单

| 页面 | 地址 | 谁能看 | 内容 |
|-|-|-|-|
| 落地页 | `/` | 所有人 | 产品展示，不可操作；按钮未登录时去登录页，已登录时去创作页 |
| 登录页 | `/login` | 未登录 | 手机号 + 验证码；勾选同意协议 |
| 创作页 | `/create` | 已登录 | 继续上次学习、新建表单、学习记录 |
| 阅读与闯关页 | `/book/{id}` | 书的主人 | 正文、逐题闯关、目录、阅读设置、等待页 |
| 结局画廊 | `/book/{id}/gallery` | 书的主人 | 已收集 / 未解锁结局、重走结局 |
| 个人中心 | `/me` | 已登录 | 头像与昵称、手机号（打码显示）、学习统计（读过几本、通关几章）、退出登录、协议入口 |
| 用户协议 / 隐私政策 | `/terms`、`/privacy` | 所有人 | 法律文本（演示版先放标准范本，上线前请专业人士审定） |

### 4.4 关键流程

**首次使用：**

1. 打开落地页，看产品介绍和示例。
2. 点任意按钮（如「开始学习」）→ 跳转登录页。
3. 输入手机号 → 获取验证码 → 填验证码，勾选同意用户协议和隐私政策 → 登录成功（新手机号自动注册）。
4. 进入创作页（或登录前想去的页面）。

**学习主流程：**

1. 创作页输入「你想学什么」→ 选故事类型 → 选想学多深 → 开始生成。
2. 系统生成书名、全书大纲、故事档案、随机暗定结局（不透露），**大纲写好后自动接着写第一章**；等待页一条步骤条显示全程进度，可以离开页面。
3. 循环：读本章 → 章末进入闯关，逐题作答、即时判对错 → 答对 3 题通关，得到本章知识卡片；用户闯关时，后台已在提前写下一章。
4. 没过关则进入失败降级。
5. 读完计划章节或选择「就此完结」→ 生成大结局章（回收全部伏笔）。
6. 完结后解锁「结局画廊」，可重走其他结局。

## 5. 功能需求与验收

### 5.1 F1 新建小说

用户在创作页填写：

| 项 | 方式 | 说明 |
|-|-|-|
| 你想学什么 | 输入框（必填，≤ 60 字）+ 示例标签（复利、英语时态、蝴蝶效应、光合作用、博弈论，点一下就填入） | 过敏感词校验 |
| 故事类型 | 卡片单选：爽文 / 言情 / 都市 / 玄幻 / 悬疑，每个配一句说明 | 默认爽文 |
| 想学多深 | 卡片单选：快速了解（1 章短篇）/ 系统学习（5 章，默认）/ 深入掌握（10 章） | |
| 更多设置（默认收起） | 计划章节 1–50、每章最少字数（默认 1500）、最多字数（默认 2500） | 给想细调的用户 |

系统在创建时：取一个书名（学习记录与阅读页显示书名，学习主题作为副标题）、生成全书大纲（三幕结构）、建立故事档案、随机暗定结局风格（不透露），**大纲完成后自动开始生成第 1 章**。

验收：

- 给定主题 + 类型 + 深度，系统能创建书籍并生成覆盖全部章节的三幕大纲。
- 结局风格从 4 种（圆满 / 反转 / 开放 / 悲剧）中随机选出且界面上不展示。
- 大纲完成后不需要用户再点按钮，第 1 章自动开始生成；第 1 章生成失败时可手动重试。
- 未登录时不能新建。

### 5.2 F2 快速短篇

选择「快速了解」档：以输入的词为核心知识点，自动补 2 个关联辅助知识点，生成 1 章短篇 + 5 道测验。本质为 planned_chapters=1 的书籍，复用 F4–F9 全部逻辑。

验收：选「快速了解」后能生成 1 章含该词的短篇与 5 道题。

### 5.3 F3 逐章生成与阅读

**生成方式：**
- 第 1 章在大纲完成后自动生成。
- 之后每一章都提前生成：用户进入本章闯关时，后台开始写下一章（最后一章除外）。本章通关前读不到下一章。

**单章要求：**
- 正文目标 1500–2500 字，可接受到约 4000 字，少于最少字数要重写。
- 每章 5 道题，正文标注「（AI 生成内容）」。
- 每章固定 3 个知识点（1 核心 + 2 辅助）。

**阅读体验：**
- 目录抽屉。
- 字号四档。
- 纸白 / 护眼 / 夜间三种背景。
- 记住读到哪一段，回来后定位到原处。

**等待页：**
- 一条步骤条显示进度（新书合并显示：构思大纲 → 设定人物 → 写第一章 → 审核出题 → 完成），并显示已等待时间。
- 等待时可以看：上回说到、复习卡片、登场人物。

验收：

- 单章正文不少于最少字数、最多约 4000 字，题目数为 5，含「AI 生成内容」标注。
- 本章通关之前，读不到已提前生成的下一章。
- 关闭页面再回来，等待进度和阅读位置都能恢复。

### 5.4 F4 逐题闯关与解锁

**怎么答：**
- 每章 5 道题，一题一屏，作答后立即判对错。
- 答错的题显示讲解，可「回看原文」，跳到对应段落并高亮。
- 每道题以第一次作答为准，作答记录存后台，中途离开可以接着答。

**怎么算过关：**
- 答对 ≥ 3 题通关，解锁下一章，并展示本章知识卡片。

**题目怎么出：**
- 核心知识点 3 题（记忆 → 理解 → 迁移），2 个辅助知识点各 1 题。
- 题目只考学习主题的概念、原理和实际应用，不考人物、剧情和场景细节。
- 出题后打乱选项，正确答案不能集中在同一个位置。
- 正确答案只在作答后由后端返回，不提前发给浏览器。

验收：

- 答对 3 题及以上解锁下一章；不足 3 题不解锁。
- 题目只覆盖本章 3 个知识点；5 道题里没有考剧情的题。
- 每题能回溯到对应段落；作答前浏览器拿不到正确答案。

### 5.5 F5 失败降级（绝不卡死用户）

| 连续失败次数 | 系统行为 |
|-|-|
| 第 1 次 | 展示错题 + 原文位置；可重读；换一套新题 |
| 第 2 次 | 提示「题目可能偏难」，换偏简单的题 |
| 第 3 次及以上 | 降到最易（答案直接在原文里） |

核心原则：**难度可一路降到送分题，理论上一定能过，绝不永久卡死。**

验收：答错后能看到错题对应原文段落；重新答题时题目与上一套不同；连续失败 3 次后题目为送分题。

### 5.6 F6 章节衔接（全书大纲 + 故事档案）

生成第 1 章前先生成全书大纲（三幕结构，章节区间完整覆盖）。维护随章节更新的故事档案：人物卡、主线设定、每章一句话摘要、未回收伏笔、已学知识点清单。每章生成时注入前情摘要 + 人物卡 + 未回收伏笔。

验收：第 N 章人物设定与第 1 章一致；大纲无空档；后续章节不重复已学知识点出题。

### 5.7 F7 内容审核与连贯性校验

生成内容必须通过审核（模型自审 + 关键词兜底），不写暴力 / 色情 / 违法 / 危险模仿内容，不过则重写（最多 2 次）。每章生成后校验人物、关系、前情与档案是否一致，矛盾则自动重写。用户输入的学习主题也要过关键词校验。

验收：不安全的内容不会交付给用户；审核 / 校验不通过时自动重写，超过 2 次提示「这一章没写好，请稍后重试」。

### 5.8 F8 完结与结局画廊

任意章节通关后可选「继续下一章」或「就此完结」（需二次确认）；选完结立即生成大结局章（回收全部伏笔）。结局风格开书时暗定、全程不透露。完结后解锁「结局画廊」，可「重走一个结局」（需二次确认）——只重新生成大结局章，可收集多结局，已收集的结局可以重新阅读。

验收：阅读过程中不展示暗定结局风格；大结局回收全部未回收伏笔；重走结局不改动已有正文章节。

### 5.9 F9 进度保存与续读

记录每个账号每本书的解锁进度、作答记录、连续失败次数；登录后从上次进度继续（读到哪一段、字号、背景等偏好存在当前浏览器）。

验收：退出登录再登录，书和进度都在；服务重启后书和进度都在。

### 5.10 F10 手机号登录（演示版）

**流程（登录和注册是同一个页面）：**

1. 输入 11 位手机号 → 点「获取验证码」，按钮进入 60 秒倒计时（只做界面效果）。
2. 填 6 位验证码，勾选「我已阅读并同意《用户协议》《隐私政策》」→ 点「登录」。
3. 新手机号自动注册并登录，老手机号直接登录；进入创作页（或登录前想去的页面）。
4. 登录状态保持 30 天；个人中心可退出登录。

**演示版的宽松规则：**

- **不发真实短信**：验证码统一使用一个固定的演示码，由演示者掌握，页面上不显示。真正上线时换成真实短信。
- 不做防刷、图形验证和限频，不需要内测码。
- 手机号只校验格式（11 位、1 开头）。

**仍要做到：**

- 未登录访问创作页、阅读页、结局画廊、个人中心，都会被带到登录页；业务接口返回「未登录」错误。
- 每个账号只能看到、打开自己的书（权限在后端判断，改地址里的书号也打不开别人的书）。
- 本机现有 17 本书归到产品经理的演示账号名下，作为演示数据；迁移前整库备份。

验收：

- 未登录点击落地页任意按钮，都进入登录页；登录后回到原本要去的页面。
- 用演示码能登录；验证码错误时提示「验证码不正确」。
- 换一个手机号登录，看不到演示账号的书。

### 5.11 F11 落地页（只展示，不可操作）

落地页的任务是讲清楚「悦读能做什么」，**页面上不提供任何实际操作**。

**内容（从上到下）：**

1. **首屏**：标语「读进故事里，把知识带出来」+ 一句说明 + 主按钮「开始学习」+ 插画；右上角「登录」按钮（已登录时显示头像，点了去创作页）。
2. **三步说明**：写下想学的 → 读为你写的小说 → 答题解锁下一章。
3. **示例展示**：一段静态小说节选 + 一道示例题的展示（不能真的作答）。
4. **常见问题**：内容是谁写的（AI 生成，已审核）、要多久能读到（约 2–4 分钟）、适合学什么。
5. **页脚**：用户协议、隐私政策、联系邮箱、版权信息。

验收：未登录状态下，落地页没有任何输入框或可提交的操作；点任意按钮都进入登录页。

### 5.12 F12 学习记录与「继续上次学习」

位于创作页：

- **继续上次学习**：放在顶部，显示主题、书名、已闯过几章 / 共几章，点了直接回到那本书。
- **学习记录**：默认显示最近 4 本，可「查看全部」。卡片突出学习主题，书名作副标题，带进度条和「学习中 / 已完结」标记。
- 只显示当前账号自己的书。

### 5.13 F13 个人中心 + 协议页

- **个人中心**：
  - 头像（按昵称首字生成）和昵称（默认「悦读用户 + 手机尾号」）。
  - 手机号打码显示（如 138****5678）。
  - 学习统计：读过几本、通关几章、学会几个知识点。
  - 退出登录。
  - 用户协议、隐私政策入口。
- **用户协议 / 隐私政策**：独立页面，落地页页脚和登录页都能打开。

所有页面顶栏右侧统一显示登录状态，未登录显示「登录」，已登录显示头像。

### 5.14 F14 我学会了什么 + 错题本（P1）

- **我学会了什么**：按书汇总所有已通关章节的知识卡片，可搜索、可复习。
- **错题本**：汇总答错过的题和讲解，可以重新做一遍（不影响已有进度）。

## 6. 异常与边界

| 场景 | 处理 |
|-|-|
| 生成调用失败 | 自动重试 1–2 次，仍失败提示「稍后再试」，不扣额度 |
| 审核 / 篇幅 / 连贯性不通过 | 自动重写，最多 2 次 |
| 单章超时（> 3 分钟） | 提示「仍在生成中」，不阻塞已解锁章节 |
| 每月费用到上限 | 提示「生成服务暂时休息」，已生成内容照常阅读 |
| 登录过期 | 带到登录页，登录后回到原页面 |
| 验证码填错 | 提示「验证码不正确」，可重填 |
| 越权访问（别人的书、未解锁章） | 拒绝，页面提示「这本书不存在」 |

## 7. 安全与质量底线（演示版也要做到）

- 内容审核：模型自审 + 关键词兜底，用户输入主题也要审。
- 正文标「（AI 生成内容）」；登录需同意用户协议和隐私政策，不收集年龄自声明。
- 每个账号只能看自己的数据，权限判断在后端。
- 模型密钥只存在服务器，不进前端、不进代码仓库；日志不记录密钥和完整正文。
- 单章生成时延 ≤ 3 分钟；新书从提交到读到第 1 章 ≤ 5 分钟。
- 书籍、进度、作答记录、生成任务全部持久化，服务重启后可恢复。
- 每月模型费用上限 50 元，到顶自动停止生成。
