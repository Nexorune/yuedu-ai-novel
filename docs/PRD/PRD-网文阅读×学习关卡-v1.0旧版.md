# 产品需求文档（PRD）：网文阅读 × 学习关卡

| 项目 | 内容 |
|---|---|
| 产品名（暂定） | 网文阅读 × 学习关卡 |
| 文档版本 | v1.0 |
| 状态 | 终稿（待评审） |
| 目标平台 | MVP：单进程 Python 应用（CLI）；后续可迁移 Web / 小程序 |
| 目标上线 | MVP 验证期 |

---

## 1. 产品概述

### 1.1 背景与问题

市面上的学习产品（背单词、刷题、知识付费）普遍存在两个痛点：

1. **学习反人性**：用户知道「应该学」，但缺乏持续动力，打卡难以坚持，留存普遍偏低。
2. **网文只有爽感没有收获**：用户沉迷追更，但读完「除了爽什么都没留下」，事后有愧疚感，也难以形成长期价值沉淀。

### 1.2 产品定位

一款**把「追网文的爽感」和「学习打卡」绑定**的生成式内容产品：用户选小说类型 + 输入想学的主题，系统按章生成个性化小说与配套测验，答对解锁下一章。

一句话价值主张：**「边追更，边学东西」——每一章爽完之后，顺手把知识带走。**

### 1.3 核心价值

| 对象 | 获得的价值 |
|---|---|
| 用户 | 低门槛、无痛的学习体验；每本书内容完全个性化，独一无二 |
| 产品方 | 高留存的内容消费形态；生成式内容边际成本极低 |

### 1.4 与竞品的差异

| 维度 | 传统刷题/知识付费 | 本产品 |
|---|---|---|
| 学习动力 | 靠意志力/外部监督 | 靠「追更爽感」+「解锁闯关」内在驱动 |
| 内容形态 | 固定课程、固定题库 | 按用户类型+主题实时生成的个性化小说 |
| 留存抓手 | 打卡、连续天数 | 剧情钩子 + 多结局收集 |

## 2. 目标与成功标准

### 2.1 北极星指标

**周留存率**：本周至少完成 1 次答题的用户，在下周仍至少完成 1 次答题的比例。

### 2.2 分阶段目标

| 阶段 | 目标 | 判定标准 |
|---|---|---|
| MVP 验证期（上线 4 周） | 验证「边追边学」模式成立 | 周留存 ≥ 30% |
| 增长期 | 验证规模化与变现 | 周留存 ≥ 30%，单用户日均 1–3 章 |

### 2.3 指标体系

| 指标 | 目标值 | 说明 |
|---|---|---|
| 周留存 | ≥ 30% | 核心指标，自然周口径，连续观察 4 周 |
| 单章完读率 | ≥ 60% | 读完正文才进入答题的用户占比 |
| 答题正确率 | 50%–70% | **区间指标**：低于 50% 说明题太难（劝退），高于 70% 说明题太简单（没学到东西），均触发难度调整 |
| 单章生成时延 | ≤ 3 分钟 | 异步生成，用户提交后先返回 |
| 单章生成成本 | ≤ 几分钱 | 受 max_tokens 护栏约束 |

## 3. 目标用户

### 3.1 用户画像

- **年龄段**：18–35 岁
- **核心特征**：爱看网文（爽文/言情/都市等），同时有碎片化学习意愿（想学 AI、英语、理财等，但坚持不下来）
- **典型场景**：通勤、睡前、午休等碎片时间，手机阅读
- **使用方式**：单用户线性使用，非多人协作

### 3.2 用户故事

1. 作为「想学 AI 但看不进教材」的用户，我希望能用爽文的形式学 AI 概念，这样我能坚持读完。
2. 作为「只有 3 分钟碎片时间」的用户，我希望输入一个词（如「复利」）就能立刻得到一篇短故事 + 测验。
3. 作为「读到一半失去兴趣」的用户，我希望随时能「就此完结」，得到一个有头有尾的结局，而不是烂尾。
4. 作为「喜欢收集」的用户，我希望完结后还能解锁不同风格的结局，反复体验。

### 3.3 使用频率假设

- 目标日活用户平均读 1–3 章/天（用于容量估算，非硬性约束）。

## 4. 功能需求

### 4.0 功能总览

| 编号 | 功能 | 优先级 |
|---|---|---|
| F1 | 新建小说（选类型 + 主题 + 章节数 + 篇幅） | P0 |
| F2 | 快速短篇（单知识点 → 短篇 + 测验） | P0 |
| F3 | 逐章生成与阅读 | P0 |
| F4 | 答题与解锁（5 题对 3） | P0 |
| F5 | 失败降级（提示/换题/降难度/争议题） | P0 |
| F6 | 全书大纲 + 故事档案（章节衔接） | P0 |
| F7 | 内容审核与连贯性校验 | P0 |
| F8 | 随时完结 + 结局随机暗定 + 结局画廊 | P0 |
| F9 | 进度保存与续读 | P0 |
| F10 | 账号登录（真实用户体系） | P1（MVP 用本地档案） |
| F11 | 支付 / 消息推送 / 独立题库 | P2（二期） |

### 4.1 F1 新建小说

用户输入：
1. **小说类型**：爽文 / 言情 / 都市 / 玄幻 / 悬疑（可扩展）
2. **学习主题**：如 AI、英语、复利（自由文本）
3. **章节数**：1–50 章
4. **每章篇幅**：最少字数（默认 1500）、最多字数（默认 2500）

系统在创建时完成：
- 为小说取独立书名，并在书架与阅读页展示；学习主题作为副信息展示
- 生成全书大纲（三幕结构，见 6.1）
- 建立故事档案（见 6.2）
- **随机暗定结局风格**（圆满/反转/开放/悲剧，不向用户透露，见 6.6）

### 4.2 F2 快速短篇

- 用户只输入**一个词或知识点**（如「蝴蝶效应」）
- 系统自动：以该词为**核心知识点**，自动补 2 个关联辅助知识点，生成 1 章短篇 + 5 道测验
- 本质是 `planned_chapters=1` 的特殊书籍

### 4.3 F3 逐章生成与阅读

- **异步生成**：第一章由用户发起；从第二章起，用户打开本章答题区时，后台提前生成下一章。答题未通过前不得读取提前生成的章节；通过后点「读下一章」直接阅读已备好的内容，尚未生成完则展示进度。
- **按章交付**：不整本一次生成；每章生成后解锁下一章入口
- 单章硬约束：**1500–2500 字正文 + 5 道题**，正文标注「（AI 生成内容）」

### 4.4 F4 答题与解锁

- 每章 5 道题，**答对 ≥3 题（60%）解锁下一章**
- 题目的三层结构（见 6.4）：
  - 核心知识点 3 题（记忆 → 理解 → 迁移）
  - 2 个辅助知识点各 1 题（定位题，答案在原文）
- 每题带 `source_paragraph`（对应段落），答错时可精确提示「回看第 X 段」
- 题目只巩固学习主题的概念、原理和现实应用。禁止以人物、剧情、虚构称号或小说场景细节作为考点；即使选项提到真实知识，题干考剧情也不合格。

### 4.5 F5 失败降级（绝不卡死用户）

| 连续失败次数 | 系统行为 |
|---|---|
| 第 1 次 | 展示错题 + 答案在原文的位置提示；用户可重读原文；「重新答题」时**换一套新题**（防背答案） |
| 第 2 次 | 提示「题目可能偏难」，换题为**偏简单**难度（答案尽量能在原文找到） |
| 第 3 次+ | 自动降到**最易**（纯定位送分题），并上报「本章内容可能有问题」 |
| 任意时 | 用户可点「这题有问题」→ 该题**作废不计分**，按剩余题数重新判定（作废 1 题后按 4 题对 ≥3 算） |

**原则：难度可一路降到「答案就在原文里」的送分题，理论上一定能过，绝不永久卡死；只有题烂才作废题，不作废整章。**

### 4.6 F8 完结与结局画廊

- **随时完结**：任意章节答完题后，可选「继续下一章」或「就此完结」；选完结立即生成大结局章（回收全部未回收伏笔），不论原计划还剩几章
- **结局随机暗定**：开书时暗中随机选定结局风格，阅读全程不透露，保持期待感；完结时按暗定风格生成
- **结局画廊**：完结后解锁，展示已解锁结局；用户可「重走一个结局」——**复用前面所有章节 + 故事档案，只重新生成大结局章**（不同风格），逐次解锁、可收集多结局

### 4.7 F9 进度与续读

- 记录用户已解锁到第几章、连续失败次数、每日生成次数
- 会话中断后可从上次进度继续

## 5. 用户流程（关键路径）

### 5.1 主流程（整本模式）

```
开始
 └─ 18+ 年龄确认
     └─ 选小说类型 → 输学习主题 → 设章节数 → 设篇幅
         └─ 系统：生成全书大纲 + 建立故事档案 + 暗定结局
             └─ 【循环】读下一章
                 ├─ 后台生成章节（大纲注入 + 档案注入 + 审核 + 篇幅校验 + 连贯性校验）
                 ├─ 展示正文
                 ├─ 答题（5 题对 3）
                 │   ├─ 通过 → 解锁下一章 → 回到【循环】
                 │   └─ 失败 → 失败降级（提示/换题/降难度）→ 重新答题
                 └─ 读完计划章节 → 提示可「就此完结」
     └─ 就此完结 → 生成大结局章（按暗定结局，回收全部伏笔）→ 全书完结
         └─ 结局画廊：可重走其他结局
```

### 5.2 快速短篇流程

```
输入一个词/知识点 → 生成 1 章短篇 + 测验 → 答题 → 完结 → 结局画廊
```

### 5.3 异常分支

| 场景 | 处理 |
|---|---|
| 生成调用失败 | 自动重试 1–2 次，仍失败则提示「稍后再试」，不扣额度 |
| 审核不通过 | 自动重写，最多 2 次；超过则降级为「保守模板章」 |
| 篇幅/题量不达标 | 自动重写，最多 2 次 |
| 连贯性不通过 | 自动重写，最多 2 次 |
| 单章超时（>3 分钟） | 中止并重排，通知用户「仍在生成中」，不阻塞已解锁章节 |
| 越权访问（读未解锁章） | 拒绝并记录 |

## 6. 生成引擎设计

### 6.1 全书大纲（三幕结构）

生成第 1 章之前，先让模型输出全书大纲，把总章节数分配到三幕：

```
act1（开局）：主角陷入困境，埋下核心伏笔
act2（发展）：层层升级，爽点与知识点交织
act3（高潮与结局）：最大冲突，伏笔逐个回收
```

- 三幕的章节区间必须**完整覆盖** 1 到总章数，不能有空档
- 每章生成时，prompt 注入「当前属于哪一幕 + 全书还剩几章」，让模型始终知道自己在书中的位置

### 6.2 故事档案（Story Bible）

随章节更新的持久化档案，是跨章节连贯性的唯一依据：

| 字段 | 内容 |
|---|---|
| 人物卡 | 姓名、身份、性格、当前状态、与他人的关系 |
| 主线设定 | 故事目标、核心冲突、世界观规则 |
| 章节摘要 | 每章一句话梗概 |
| 未回收伏笔表 | 已埋未揭晓的伏笔清单（status: open/resolved） |
| 已学知识点 | 已出过题的知识点，避免重复 |
| 大纲 | 三幕结构 |

**每章生成时，prompt 注入**：前 N-1 章摘要 + 最新人物卡 + 未回收伏笔 + 已学知识点。

### 6.3 单章生成（三段式）

每章严格按三段式输出 JSON：

```
① 知识点清单：1 个核心 + 2 个辅助，各一句话，标出出现段落
② 故事正文：围绕 3 个知识点写 1500–2500 字；核心点要解释含义、用法和现实例子，辅助点至少准确解释，不能只把术语当作虚构设定装饰
③ 题目：只能从①的知识点里出 5 道题
```

**关键约束：出题只能从已列的知识点清单里出，不能超纲**——保证题文对应、减少争议题、学习目标可控。

### 6.4 知识点与出题规则

- **每章固定 3 个知识点**：1 核心 + 2 辅助
- **5 道题的映射**：
  - 核心知识点 → 3 道（记忆题 / 理解题 / 迁移题，层层深入）
  - 辅助知识点 ×2 → 各 1 道定位题
- **难度梯度**：记忆题/定位题是「送分兜底」，迁移题是「真正的闯关门槛」

### 6.5 章节衔接（连贯性保证）

两层机制把「断章」概率压到最低：

1. **档案注入**：每章 prompt 都能「看到」之前的摘要和人物状态
2. **连贯性校验**：生成后跑一次校验（人物姓名/身份/关系/前情是否与档案一致），不一致自动重写

**诚实声明**：不能 100% 保证不断章，但校验兜底能在交付用户前拦截绝大部分断章。

### 6.6 结局机制

| 阶段 | 用户视角 | 系统行为 |
|---|---|---|
| 开书 | 无感知 | 随机暗定结局风格（圆满/反转/开放/悲剧），存档案，不透露 |
| 阅读中 | 不知走向，保持悬念 | 每章生成时注入隐晦基调提示（如「剧情埋有反转的种子」），但不点破 |
| 完结 | 首次看到结局 | 按暗定风格生成大结局，回收全部伏笔 |
| 完结后 | 解锁结局画廊 | 可重走其他结局（只重写大结局章，复用前面章节） |

## 7. 非功能需求

### 7.1 性能

- 单章生成时延 ≤ 3 分钟（异步，用户提交后先返回）
- 单章 1500–2500 字 + 5 题

### 7.2 成本

- 单章生成成本 ≤ 几分钱
- `max_tokens` 护栏：单章生成 4096 token
- 每日生成上限：20 章/用户/天（防滥用），失败重试不计数

### 7.3 安全与合规（硬红线）

1. **内容审核**：生成内容必须过审核（模型自审 + 关键词兜底），不写暴力/色情/违法/危险模仿，不过则重写
2. **年龄保护**：面向 18+ 成年人，MVP 用自声明确认（产品化后换实名/支付校验）
3. **版权声明**：明确「AI 生成内容」，不改编现实真实网文
4. **越权拒绝**：不能访问未解锁章节

### 7.4 可观测性

- **日志**：每章生成请求（章节号、参数、max_tokens、起止时间）、审核结果、解锁动作、工具失败与重试链
- **指标**：周留存、单章完读率、答题正确率、单章时延、单章成本
- **轨迹**：按「用户 + 章节」记录完整轨迹（生成参数 → 模型调用 → 审核 → 校验 → 落库 → 解锁 → 答题结果）

## 10. 风险与开放问题

| 风险/问题 | 说明 | 应对 |
|---|---|---|
| 章节断章 | AI 写长篇可能前后矛盾 | 故事档案 + 连贯性校验 + 自动重写 |
| 内容安全 | 生成式内容合规风险 | 模型自审 + 关键词兜底 + 18+ 门槛 + AI 标注 |
| 题目幻觉 | 答案与正文对不上 | 出题只能从知识点清单出 + source_paragraph 锚定 + 争议题作废 |
| 成本失控 | 长篇字数膨胀 | 篇幅硬限制 + max_tokens + 每日上限 |
| 「周留存 ≥30%」统计口径 | 自然周内几次答题算留存未定 | 上线前确认：≥1 次答题 |

## 12. 术语表

| 术语 | 含义 |
|---|---|
| 爽文 | 以「主角逆袭、打脸反派」为核心爽点的网文体裁 |
| 故事档案（Story Bible） | 随章节更新的持久化档案，保证跨章连贯 |
