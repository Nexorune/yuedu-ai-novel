# 技术适配声明（v2：网页版优先）

> 项目：悦读（网文阅读 × 学习关卡）｜日期：2026-09-28｜阶段：1 技术适配
> 依据：PRD v1.0 终稿 + 通用技术栈手册第一至六节 + 现有代码 `backend/novel_learning/` 自检 + 产品经理决定「网页版优先」

## 1. 产品形态判断
- 产品类型与核心任务：生成式内容产品。用户选小说类型 + 学习主题 + 章节数 + 篇幅，系统逐章生成个性化小说与配套测验，答对解锁下一章；价值主张「边追网文，边学知识」。
- 核心交互：分阶段生成（逐章异步）+ 阅读与答题（同步）。读 1500–2500 字正文 + 答题的体验天然适合网页，CLI 不适合阅读场景。
- 开发路径：**纵向切片**。阅读与答题交互是核心体验的一部分，阶段 2 直接交付「最小后端 + 最小网页界面 + 真实模型」的端到端链路，而不是先做纯后端再补界面。
- 当前阶段范围：阶段 2 = 后端（FastAPI 封装现有核心模块）+ 最小网页验收界面（本地浏览器打开 localhost），验证核心链路；正式 Next.js 前端留到阶段 3。

## 2. 采用的默认方案
| 方案 | 采用原因 |
| --- | --- |
| Python 3.12.x | 现有代码 3.12 语法（`from __future__ import annotations`、`dataclasses`），本机 python3.12（3.12.14）就绪 |
| FastAPI | 把现有生成/判题/进度能力做成网页可调用的 API（手册默认后端框架） |
| 最小网页界面：单个 HTML + 原生 JS + `fetch`，由 FastAPI 挂载到 `static/` | 手册第五节「最小验收界面」：阅读与答题需要「用眼睛看、亲手操作」才能判断质量；不提前铺开 Next.js |
| SQLite（单文件，`data/novel_learning.db`） | PRD 8.2 明确；单用户本地，不引入 ORM/Alembic |
| 模型调用：anthropic 官方 SDK + Anthropic 兼容网关（DeepSeek） | PRD 明确 DeepSeek；现有 llm.py 已实现模型无关封装 |
| 数据校验：dataclasses（现有）+ llm.call_json 稳健解析 | 结构校验已内建，无需 Pydantic |
| 测试：pytest | 现有无测试，阶段 2 补齐 mock 自动化测试 |
| 代码管理：Git | 项目已在 Git 仓库内，不重复初始化 |
| 终端：网页版（最小 HTML 界面，阶段 2）；正式 Next.js 前端（阶段 3） | 产品经理决定网页版优先 |

## 3. 触发的按需模块
- **无新增**。内容审核 = 模型自审 + 关键词兜底（现有 security.py 内建）；无 RAG / PDF / docx / OCR / SSE / 任务队列需求；单用户本地 + FastAPI 即可满足 MVP。
